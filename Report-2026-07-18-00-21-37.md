## 1. Punca Utama Ralat: `react-hooks/set-state-in-effect` (React 19 Specification)

### Mengapa Ralat Ini Muncul Sekarang?
Pangkalan kod projek menggunakan piawaian **React 19 (`"react": "^19.2.6"`)** bersama pemalam **`eslint-plugin-react-hooks@7.1.1`**. Dalam versi terbaru ini, pasukan penuangan React telah menguatkuasakan peraturan pengesanan yang lebih ketat terhadap penggunaan Hook `useEffect`.

Ralat ini berlaku apabila fungsi `setState` dipanggil **secara segerak (synchronously)** langsung di dalam badan `useEffect` tanpa sebarang syarat luaran atau langganan asinkronus (*async subscription*).

### Apakah Fenomena *Cascading Renders* (Re-render Berangkai)?
Mengikut dokumentasi rasmi React ([You Might Not Need an Effect](https://react.dev/learn/you-might-not-need-an-effect)), `useEffect` direka semata-mata untuk **menyelaraskan state React dengan sistem luaran** (seperti pengurusan DOM manual, panggilan API, atau WebSocket/Event Listener).

Apabila anda memanggil `setState` secara segerak di dalam `useEffect`:
1. **Langkah 1:** React selesai melakukan komputasi render pertama berdasarkan *props/state* semasa.
2. **Langkah 2:** React mengemas kini DOM dan bersiap untuk memaparkan visual (*paint*) ke skrin.
3. **Langkah 3:** `useEffect` dijalankan serta-merta selepas komit pertama.
4. **Langkah 4 (Punca Masalah):** Panggilan `setState` di dalam `useEffect` memaksa React membuang paparan visual yang baru sahaja disiapkan, dan **terus melancarkan kitaran re-render kedua secara merta**.

Kesan negatif daripada *Cascading Renders*:
- **Pembaziran CPU & Penurunan Prestasi:** Pengiraan komponen, perbandingan Virtual DOM, dan pemprosesan jadual dilakukan dua kali bagi setiap satu interaksi pengguna.
- **Kelipan Visual (*UI Flickering/Layout Shift*):** Pengguna mungkin melihat sekilas nilai lama sebelum ia ditukar kepada nilai baharu.
- **Risiko *Infinite Loop*:** Sekiranya dependencies `useEffect` tidak dijaga rapi, panggilan `setState` akan memicu `useEffect` tersebut berulang kali tanpa henti hingga melumpuhkan pelayar.

## 2. Pecahan Terperinci 15 Masalah Semasa (*The 15 Problems Breakdown*)

Berikut adalah senarai tepat 15 masalah yang dikesan oleh ESLint dan IDE pada fail-fail utama projek:

### Kategori A: Ralat Kritis *Cascading Renders* (`react-hooks/set-state-in-effect`)

#### 1. `ProductModal.jsx` (Baris 88:13)
```javascript
useEffect(() => {
    if (isOpen) {
        const pricingObj = product?.ProductPricing;
        const pricing = Array.isArray(pricingObj) ? (pricingObj[0] || {}) : (pricingObj || {});
        setFormData({ ... }); // ❌ Ralat: Memanggil setState segerak dalam effect
    }
}, [isOpen, product, prefilledName]);
```
- **Analisis:** Setiap kali modal dibuka atau `product` / `prefilledName` berubah, `setFormData` dipanggil di dalam `useEffect` untuk mengisi borang. Ini menyebabkan komponen `ProductModal` dirender sebanyak 2 kali berturut-turut setiap kali pengguna mengklik butang *SKU Review* atau *Edit Product*.

#### 2. `AllOrders.jsx` (Baris 65:9)
```javascript
useEffect(() => {
    SetRowSelection({}); // ❌ Ralat: Memanggil setState segerak apabila filter berubah
}, [ActiveTab, FilterAgent, FilterPlatform, FilterAccount, QueueSortBy, HistorySortBy, FilterMonth, DateRange.from, DateRange.to]);
```
- **Analisis:** Digunakan untuk mengosongkan tanda kotak pilihan (*checkbox selection*) apabila pengguna menukar tab atau penapis saringan. Kerana ia berada dalam `useEffect`, selepas jadual pesanan dirender semula dengan data baharu, satu lagi re-render dipicu semata-mata untuk mengosongkan objek `RowSelection`.

#### 3. `PriceSetup.jsx` (Baris 15:9)
```javascript
useEffect(() => {
    setLocalValue(value ?? ''); // ❌ Ralat: Memanggil setState segerak pada input harga
    setPrevValue(value);
}, [value]);
```
- **Analisis:** Komponen `PriceInput` cuba menyelaraskan nilai input tempatan (`localValue`) apabila *prop* `value` dari jadual utama berubah. Memandangkan halaman `/Price/Setup` mengandungi ratusan kotak input, panggilan `setState` dalam `useEffect` bagi setiap baris input menyebabkan bebanan re-render berskala besar yang melambatkan tindak balas jadual.

## 3. Cadangan Pembetulan Arsitektur Mengikut Piawaian React 19

Untuk menyelesaikan ralat ini secara kekal tanpa menjejaskan kestabilan sistem atau menambah kompleksiti kod, berikut adalah amalan terbaik yang disarankan oleh React:

### A. Pembetulan untuk `ProductModal.jsx` (Teknik Reset Menggunakan Prop `key`)
Daripada menggunakan `useEffect` untuk menyusun semula borang apabila modal dibuka, jadikan peraknaan awal state (`useState`) bergantung langsung kepada prop `product` dan `prefilledName`.

Untuk memastikan state diinisialisasi semula dengan bersih apabila produk baharu dipilih, **luluskan prop `key` unik dari komponen induk (`AllOrders.jsx` & `ProductMatcher.jsx`) semasa memanggil `<ProductModal />`:**

```javascript
// Di dalam AllOrders.jsx / ProductMatcher.jsx:
<ProductModal
    key={SkuReviewItem?.ItemID || SkuReviewItem?.ProductID || prefilledName || 'new-modal'}
    isOpen={IsProductModalOpen}
    onClose={() => SetIsProductModalOpen(false)}
    product={null}
    prefilledName={SkuReviewItem?.ProductName || ''}
    onSuccess={handleProductModalSuccess}
/>
```
Apabila `key` bertukar, React secara automatik akan memusnahkan (*unmount*) instance modal lama dan mencipta instance baharu dengan *state* `formData` yang segar dari `useState()`. Ini menghapuskan keperluan `useEffect` dan `setFormData` segerak 100%.

### B. Pembetulan untuk `AllOrders.jsx` (`SetRowSelection`)
Kosongkan pilihan baris (*row selection*) secara langsung **di dalam *Event Handler*** apabila pengguna mengklik tab atau mengubah saringan, bukannya menunggu `useEffect`:

```javascript
// Pengendali pertukaran tab yang bersih:
const handleTabChange = (newTab) => {
    setActiveTab(newTab);
    SetRowSelection({}); // Mengosongkan pilihan serentak dalam batch render yang sama!
};
```
Atau sekiranya pengosongan automatik semasa perubahan prop saringan diperlukan, gunakan corak **Deriving State during Render (Trend Adjustment)**:
```javascript
const [prevFilterKey, setPrevFilterKey] = useState(currentFilterKey);
if (currentFilterKey !== prevFilterKey) {
    setPrevFilterKey(currentFilterKey);
    SetRowSelection({}); // Benarkan penyesuaian state semasa render sebelum komit DOM
}
```

### C. Pembetulan untuk `PriceSetup.jsx` (`PriceInput`)
Bagi komponen berinput tinggi seperti `PriceInput`, elakkan `useEffect` sepenuhnya untuk menyelaraskan prop dengan state tempatan. Gunakan pengiraan langsung atau penyesuaian semasa fasa render:

```javascript
const PriceInput = ({ value, onChange, disabled, type = 'selling', costPrice = 0, sellingPrices = [] }) => {
    const [localValue, setLocalValue] = useState(value ?? '');
    const [prevValue, setPrevValue] = useState(value);

    // Penyesuaian state semasa render (Mengelakkan cascading render dari useEffect)
    if (value !== prevValue) {
        setPrevValue(value);
        setLocalValue(value ?? '');
    }
    // ... baki logik input
};
```

### D. Pembetulan untuk `no-unused-vars`
1. Buang semua impot ikon dan komponen UI (`Dialog`, `navigate`, `MergeAndPrintAwbs`) yang tidak digunakan di bahagian atas fail.
2. Tandakan parameter yang tidak digunakan dalam fungsi *callback* dengan awalan garis bawah (`_`), contohnya:
```javascript
const handleProductModalSuccess = async (newProductId, _productData) => {
    // _productData memberitahu ESLint bahawa parameter ini sengaja diabaikan
    if (!SkuReviewItem || !newProductId) return;
    // ...
};
```
